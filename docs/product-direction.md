# 产品方向与优化路线

Meta Code 的核心价值是把多个本地 Agent 组织成一个可恢复、可审查、可交付的开发流程。用户不需要记住每个 CLI 的启动方式，也不需要在多个窗口之间手工转交上下文；他们只需要给出目标，工作台负责准备执行环境、记录过程、汇总产物并保留人工接管点。

## 当前优先服务的用户

项目优先服务已经使用 Codex、Claude 或 ACP Agent 的个人开发者，尤其是需要处理跨文件改造、代码审查、测试补全、依赖升级和长时间运行任务的人。单一 Agent 的简单问答不是主要差异点；可恢复执行、清晰 Diff、验证结果和失败后的继续处理才是核心体验。

## 近期产品原则

1. **先交付结果，再展示平台能力。** 首次进入工作台应能在几分钟内完成一次有明确验证步骤的任务。
2. **每次修改都可审查。** Agent 的文件修改、命令、测试和风险必须能回到同一个任务记录中。
3. **长任务必须可恢复。** 重启、网络波动、CLI 更新或单个节点失败不能丢失上下文，也不能把失败伪装成成功。
4. **并发必须可控。** 互相独立的任务可以并行；可能修改同一范围的任务必须先隔离或等待人工处理。
5. **用户始终知道代价。** 任务页应逐步补充 Token、耗时、失败原因和 Provider 选择的可见性。

## 交付路线

### P0：完成第一次成功任务

- 通过代码审查、修复 Bug、补全测试、升级依赖四个模板引导用户开始。
- 首次任务显示工作区、执行模式、验证步骤和结果位置。
- README、安装说明、版本号和平台支持范围保持一致。
- 以“首次成功任务时间”和“完成后仍可复现”作为验收指标。

### P1：让交付过程值得信任

- 为工作流节点提供独立 Diff、测试结果、产物清单和失败原因。
- 引入 Git worktree 或补丁隔离，减少并行写入冲突。
- 允许暂停、恢复、重试和人工接管，并在最终交付前执行统一验收。
- 在任务级别展示 Token、耗时、Provider、重试次数和验证通过率。

### P2：形成可复用的项目资产

- 保存项目级任务模板、上下文规则和验收命令。
- 根据任务类型和 Provider 能力提供可解释的模型建议。
- 导出交付报告，包含变更、测试、风险和后续清单。
- 在个人本地体验稳定后，再评估团队同步、权限和云端能力。

## 可参考的产品

- Cursor、Windsurf：上下文获取和代码内反馈。
- Aider：Git 优先、任务范围小、交付结果明确。
- Cline、Roo Code：工具权限审批和 Provider 可替换性。
- OpenHands：长任务、沙箱和可恢复执行。
- Continue、Zed：本地优先、扩展接入和界面性能。
- LangGraph、Temporal：持久化状态、重试、恢复和运行可观察性。
- GitHub Copilot coding agent：从目标、分支、测试到 Diff 的完整交付闭环。

## 发布前质量门槛

- `npm run typecheck` 通过。
- `npm run build` 通过，首屏不加载重量级 Markdown/图表预览依赖。
- 离线回归测试全部通过，且 Provider 路径测试在 Windows、macOS、Linux 上不依赖固定分隔符。
- 关键用户路径至少覆盖：首次创建任务、运行、暂停/恢复、失败重试、查看 Diff、导出或恢复数据。
