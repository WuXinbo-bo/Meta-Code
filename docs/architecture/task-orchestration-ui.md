# 任务编排模式前端交互技术方案

> 状态：设计基线（Approved UX Direction）  
> 版本：1.0  
> 日期：2026-08-10  
> 关联后端基线：[task-orchestration.md](task-orchestration.md)

## 1. 目标

为工作台新增一套独立的“任务编排模式”前端体验：用户输入一个完整任务，查看 AI 生成的任务计划，批准后观察多个子 Agent 按依赖执行，最后查看统一成果。

核心体验是：

> 一个工作台、一张任务画布、一个随阶段变化的操作区。

设计参考 Google Stitch 的空间化画布和 Apple HIG 的层级、克制、反馈与动效原则，同时保持当前工作台的灰白底、低对比度边框、克制绿色和紧凑生产工具风格。

## 2. 不变边界

### 2.1 与现有模式并存

任务编排模式是新入口，不替换现有自由对话模式。

- 自由对话：保留现有 Claude/Codex 主脑、聊天、委派和 Agent 抽屉行为。
- 任务编排：进入独立编排工作台，使用计划审批和任务图。
- 两种模式共享模型、Skill、工作区、日志和执行器，但不共享上层 UI 状态机。

### 2.2 第一版必须保持简单

第一版 MUST：

- 使用自动布局的静态任务图。
- 允许点击节点查看和编辑详情。
- 通过底部统一操作 Dock 完成当前阶段的主要动作。
- 允许画布平移、缩放和适应画布。
- 让执行状态、依赖、产物、日志和异常可追踪。

第一版 MUST NOT：

- 提供拖拽连线或任意图形编辑器。
- 在画布中展示每个 Skill、每条日志或每个系统事件为独立节点。
- 使用多个嵌套弹窗完成主要流程。
- 使用全屏错误大卡片遮挡任务图。
- 让流式更新强制抢夺用户画布视角。

## 3. 页面骨架

```text
┌──────────────────────────────────────────────────────────────┐
│ 返回  任务名称              规划 · 审批 · 执行 · 交付   状态 │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                 无限画布 / 自动排列任务图                    │
│                                                              │
│           任务卡片、依赖连线、成果卡片和状态反馈              │
│                                                              │
│  －  82%  ＋  适应画布                      4 Agent · 3 运行中 │
├──────────────────────────────────────────────────────────────┤
│  当前阶段操作 Dock：输入 / 审批 / 执行控制 / 异常处理 / 交付 │
└──────────────────────────────────────────────────────────────┘
```

## 4. 页面分层

### 4.1 全局工作区栏

复用当前工作区侧栏，但进入任务编排时默认折叠，以最大化画布空间。

用户仍可展开它来：

- 切换工作区
- 切换任务
- 返回自由对话
- 打开 Agents、MCP 和配置

工作区栏不是任务图的一部分，不应把工作区、任务和节点混合显示。

### 4.2 顶部阶段栏

只展示四个阶段：

```text
规划 → 审批 → 执行 → 交付
```

阶段栏用于定位，不是复杂步骤编辑器。右侧只保留：

- Claude/Codex 双模型状态
- 工作流整体状态
- 暂停
- 取消
- 更多操作

并发数、Token、Skill 数量等次级信息不放在顶部主区域。

### 4.3 中央无限画布

画布是任务编排模式的主要工作区域。节点由系统自动布局，用户只负责浏览、选择和查看详情。

画布操作：

- 拖动空白区域平移。
- 触控板双指平移。
- `Ctrl + 滚轮` 或触控板捏合缩放。
- 双击空白区域适应全部节点。
- 左下角提供缩小、比例、放大和适应画布。
- 节点过多时才显示概览导航。

画布缩放和移动状态可以保存在当前工作流本地 UI 状态中，但不写入任务业务状态。

### 4.4 右侧上下文检查器

检查器默认隐藏，点击节点后从右侧滑出，宽度建议 340～380px。

检查器内容按阶段变化：

- 审批阶段：允许编辑节点定义。
- 执行阶段：显示状态、日志、尝试记录和错误。
- 交付阶段：显示结果、产物、测试和风险。

它是单层上下文面板，禁止在其中继续嵌套多层卡片和弹窗。

### 4.5 底部操作 Dock

底部 Dock 是页面唯一的主操作区，根据阶段变化。

输入阶段：

```text
[完整描述你希望完成的任务……                    ]
[附件] [工作区] [规划模型]                    [生成计划]
```

审批阶段：

```text
[填写修改意见……]                 [退回重新规划] [批准并执行]
```

执行阶段：

```text
正在执行 3 / 7 · 2 个任务等待依赖             [暂停] [活动]
```

异常阶段：

```text
“前端审批界面”执行失败                       [重试] [重新规划] [取消]
```

交付阶段：

```text
所有任务完成并通过验收                         [查看成果] [打开文件夹]
```

主操作必须在 Dock 内完成，不把“下一步”分散到多个角落。

## 5. 阶段交互

### 5.1 输入阶段

画布中央显示一个任务输入面板，不显示空的任务图。

输入内容：

- 完整任务文本
- 工作区
- 规划模型
- 附件
- 可用 Skill 范围

高级选项默认折叠。用户提交后，输入面板转为原始任务卡片。

### 5.2 规划阶段

画布逐步生成计划卡片，但必须明确提示：

```text
正在生成执行计划，尚未启动任何子 Agent
```

此阶段不显示“执行中”状态，不启动执行子 Agent，不允许用户误以为任务已经修改工作区。

### 5.3 审批阶段

画布自动适应全部节点。顶部显示计划摘要：

```text
7 个任务 · 3 批并行 · 最大并发 3 · 2 个写入任务
```

点击节点查看：

- 任务目标
- 前置依赖
- 执行模型
- Skill
- 工作区访问模式
- 写入范围
- 预期产物
- 验收标准

允许在检查器中编辑上述内容。依赖关系通过任务选择器调整，不通过拖线调整。

编辑后必须重新进行服务端校验；校验未通过时“批准并执行”按钮禁用。

### 5.4 执行阶段

画布成为实时状态面板：

- 运行中的卡片提高视觉层级并显示轻微状态动画。
- 已完成节点保持可见，但降低视觉权重。
- 依赖完成后下游节点解锁。
- 点击运行中节点打开 Agent 日志检查器。
- 节点更新不得自动重排画布。
- 用户点击“聚焦当前任务”后才移动视口。

### 5.5 异常阶段

失败节点保留原位置，下游节点显示阻塞状态。底部 Dock 只提供：

- 重试节点
- 退回重新规划
- 取消任务

错误详情放在检查器中。禁止使用遮挡整张画布的大型错误弹窗。

### 5.6 交付阶段

所有必需节点汇合到一个最终成果卡片：

```text
┌────────────────────────────┐
│ 最终成果                    │
│ 7 / 7 任务完成              │
│ 12 个产物 · 18 项测试通过   │
│                            │
│ [查看成果] [打开文件夹]     │
└────────────────────────────┘
```

右侧检查器显示摘要、文件、测试结果、风险和未完成项。

## 6. 卡片规范

### 6.1 默认紧凑卡片

```text
┌────────────────────────┐
│ ● 前端审批界面          │
│ 等待：接口契约          │
│ Codex  ✦ 2 Skills       │
│                2 / 3    │
└────────────────────────┘
```

卡片默认只显示：

- 状态点
- 两行以内标题
- 当前状态或依赖
- Claude/Codex 图标
- Skill 数量
- 简单进度

详细提示词、验收标准、写入范围、日志和产物只在检查器显示。

### 6.2 卡片交互

- 点击：打开检查器。
- 双击：聚焦卡片。
- 悬停：显示最小化操作工具栏。
- 右键：显示重试、查看日志、复制节点信息等操作。
- 键盘 `Enter`：打开检查器。
- 键盘 `Escape`：关闭检查器。

不把卡片拖动解释为修改依赖关系。第一版不允许用户拖线或改变图结构。

### 6.3 最终成果卡片

最终成果卡片比普通节点更突出，但仍保持同一套边框、圆角和阴影语言。它可以提供：

- 查看整合结果
- 打开产物文件夹
- 复制 Markdown 结果
- 查看验收记录
- 查看风险

## 7. 状态视觉语言

避免大面积彩色背景，优先使用状态点、边框、图标和局部高亮。

| 状态 | 视觉表现 |
| --- | --- |
| 等待 | 灰色状态点，降低对比度 |
| 可执行 | 蓝色状态点 |
| 运行中 | 绿色脉冲点，边框轻微高亮 |
| 已完成 | 绿色状态点 |
| 失败 | 红色边框和错误图标 |
| 需要审批 | 琥珀色状态点 |
| 被阻塞 | 灰色锁图标或低对比度 |
| 已跳过 | 降低透明度 |

连线状态：

- 未满足依赖：浅灰。
- 已满足依赖：绿色。
- 失败阻断：红色虚线。
- 当前数据流：短暂的低强度流动动画。

## 8. Skill 交互

Skill 不应作为单独大型节点出现在任务图中。

- 卡片显示最多两个 Skill 标识。
- 超出数量显示 `+N`。
- 点击卡片后在检查器中编辑 Skill。
- 规划 AI 可以推荐 Skill。
- 用户审批时确认最终 Skill。
- Skill 缺失、关闭或不可用时显示琥珀色警告。
- 每个节点只注入完成自身任务所需的 Skill。

风险分析是普通只读任务节点，不建立额外风险控制面板。

## 9. 视觉系统

### 9.1 色彩

沿用现有工作台色彩，不引入紫色渐变或大面积玻璃拟态：

- 画布背景：接近 `#f4f6f4`。
- 卡片背景：`#ffffff` 或极浅灰。
- 主强调色：现有克制绿色。
- 信息和可执行：蓝色。
- 等待和审批：琥珀色。
- 错误：红色。

### 9.2 层级

- 任务卡圆角不超过 8px。
- 普通按钮圆角约 6px。
- 阴影只用于选中、悬浮和浮层。
- 顶部工具栏可以使用轻微半透明背景。
- 任务卡保持不透明，避免文字和连线混淆。
- 页面分区使用空间和分隔线，不使用卡片套卡片。

### 9.3 排版

- 任务标题 13～14px。
- 辅助信息 10～11px。
- 页面主标题不超过当前工作区语义所需的层级。
- 不使用负字间距。
- 文本过长时省略，详情面板显示完整内容。
- 所有文本必须在卡片和按钮内部完整适配。

### 9.4 动效

- 普通状态变化：160～240ms。
- 规划生成：轻微出现和布局过渡。
- 运行状态：低强度脉冲，不持续闪烁。
- 节点更新不触发整张画布跳动。
- 尊重系统减少动态效果设置。

## 10. 响应式方案

### 10.1 桌面端

显示完整无限画布、节点连线、底部 Dock 和按需检查器。

### 10.2 窄屏端

不强行缩小整张图，切换为纵向任务列表：

```text
任务摘要
↓
当前运行
↓
等待依赖
↓
已完成
↓
失败和需要处理
```

点击节点使用底部 Sheet 查看详情。审批、重试、暂停、取消和产物查看必须保留。

## 11. 性能与稳定性约束

- 画布节点使用虚拟化或分层渲染，不能为每条日志创建画布节点。
- 事件刷新只更新受影响的节点，不重新生成整张图。
- 节点位置布局与业务状态分离，避免状态刷新导致位置抖动。
- 日志继续使用现有子 Agent 抽屉和倒序活动列表。
- SSE 断线后以工作流快照恢复，不依赖前端事件完整到达。
- 任务图状态和画布视口状态分离保存。
- 大量节点时默认聚合已完成节点，但用户可以展开。

## 12. 前端状态模型

前端至少区分以下状态：

```text
workflowSummary
planVersion
nodes
artifacts
selectedNodeId
inspectorOpen
canvasViewport
activeDockAction
```

以下状态不能混在一起：

- 画布缩放/位置不能写入业务状态。
- 检查器开关不能影响节点执行状态。
- 日志刷新不能触发任务图重新布局。
- 用户编辑草稿不能直接改已批准计划。
- 旧计划响应不能覆盖新 planVersion。

## 13. 交互反馈

优先使用局部反馈，不使用泛化红色弹窗：

- 计划校验错误：显示在对应节点字段旁。
- 执行失败：节点红色边框 + Dock 操作提示。
- 保存成功：短暂轻提示。
- 服务断线：顶部状态条提示并自动恢复。
- 产物缺失：成果卡片显示明确缺失项。
- 工作流创建后显示其独立运行目录，所有新生成的报告、导出文件和最终交付物集中收纳，避免散落在工作区根目录。

错误提示默认不自动关闭；成功、保存、复制等非错误提示短时间后自动关闭。

## 14. 第一版验收标准

前端只有满足以下条件才算完成：

1. 可以从任务创建入口进入任务编排模式。
2. 输入阶段只有一个清晰主输入框。
3. 规划阶段明确显示“尚未启动子 Agent”。
4. 审批阶段能浏览所有节点、依赖、模型、Skill、产物和验收标准。
5. 可以编辑节点并退回重新规划。
6. 审批通过前没有执行按钮可触发实际执行。
7. 执行阶段可看到并行、等待、完成、失败和阻塞状态。
8. 点击节点可以查看子 Agent 日志。
9. 失败节点可以重试、重新规划或取消。
10. 画布平移、缩放和适应画布正常。
11. 状态更新不导致画布重新跳动或节点位置改变。
12. 整合完成后能查看成果、产物、测试和风险。
13. 移动端可以用列表完成审批和执行控制。
14. 自由对话模式原有 UI 和交互无回归。

## 15. 后续实现顺序

### 阶段一：静态界面骨架

- 模式入口
- 页面布局
- 无限画布容器
- 自动节点布局
- 卡片和状态样式
- 底部 Dock
- 节点检查器

### 阶段二：审批交互

- 计划摘要
- 节点编辑
- 服务端校验反馈
- 批准、退回和版本切换

### 阶段三：执行联动

- SSE 节点状态更新
- 子 Agent 日志检查器
- 暂停、重试、重新规划和取消
- 产物和测试展示

### 阶段四：交付和稳定性

- 最终成果卡片
- 验收结果
- 重启恢复展示
- 断线恢复
- 大量节点和窄屏检查

## 16. 规范变更

以下变化必须先更新本文档版本并重新评审：

- 从只读任务图改为可拖拽编辑。
- 允许任意条件表达式。
- 将 Skill 或日志直接建模为画布节点。
- 改变底部 Dock 的主流程职责。
- 删除用户审批门禁。
- 将编排模式和自由对话合并成同一状态机。
- 引入复杂多级弹窗或多个常驻检查器。
