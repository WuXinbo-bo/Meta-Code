# 统一任务编排实现与验收

日期：2026-10-08。范围：平台无关的宿主任务上下文、编排执行和界面交互。

## 第一轮：执行目录与连续任务

- 新编排默认 `executionTarget=workspace`，业务 `executionRoot` 就是选中的项目根目录。
- 计划、事务、日志、检查点、临时原生配置放在工作台数据目录的插件运行区域，不在项目中生成额外任务目录或控制文件。
- `isolated` 和 `worktree` 是用户明确选择的执行目标，目录在原项目之外。历史任务继续使用原执行目录。
- 核心 `TaskContext` 关联对话与编排，插件保留独立状态机。模式切换不会隐式停止或重启任务。
- 从已有对话进入编排时继承真实执行目录；从 Worktree/隔离方案返回对话后再次编排，继续使用同一目录。
- 跨模型交接保留目标、消息来源、附件、决定、成果和未解决项，不复用另一个模型的原生会话 ID。
- 侧栏按任务身份聚合记录；删除和归档明确针对单条执行记录，不删除项目文件或其他关联记录。
- 文件浏览、预览、Markdown 本地链接和子 Agent 抽屉使用当前执行目录。

## 第二轮：检查点维护与局部重做

- 运行中支持显式“询问”和“调整”。询问读取进度快照，不暂停调度；状态类问题由宿主直接回答，需要解释时进入无工具快照问答。
- 调整请求先持久化，暂停新节点调度，等待已运行节点完成；生成新候选版本，批准后才能继续。
- 更换规划模型会清除不兼容的原生会话标识；修改节点模型属于合同变化，仍需审批。
- 候选展示复用、重跑、新增、删除节点和写入范围。
- 结果复用检查节点合同、依赖、输入签名和真实产物。被修改或删除的结果及其依赖不能沿用。
- 暂停或服务重启后，在消费已完成结果前重新核对文件证据。外部改动进入待处理状态；同编排后续节点的合法改动必须有实际登记和匹配的当前文件签名，不能仅凭写入范围豁免。
- 普通会话、委派、规划和编排共用工作区执行协调器，避免不同入口同时写同一项目。
- 相同或祖先目录的写入互斥；不同工作区可以并发，只读任务可以并发。委派与父任务共享执行身份。
- 只读节点的已审批验收命令由宿主执行，证据交给 Agent 审查；Claude 的 Bash 和写入权限保持禁用。
- 系统失败证据不能由结果工具改写为通过。验收仍受文件修改检查和结构化完成门禁约束。

## 第三轮：方案与工作流程

- Git 项目的方案分支使用项目外 linked Worktree；非 Git 项目使用显式隔离目标。
- 比较包含已提交差异、未提交修改和未跟踪文件。目标脏状态、冲突、过期预览或未验收方案拒绝整合。
- 未提交方案需显式确认纳入。临时 Git 索引生成不可变快照，不改变源分支、源暂存状态或源工作文件。
- 快照保留 `git add -f` 的忽略文件，支持 split-index；子目录方案不会把范围外暂存内容带入项目。
- 成功任务可以保存为带文本、相对路径或选项参数的工作流程，并保存团队模型配置。
- 实例化重新验证模型、Skill、MCP、文件范围和定义版本，创建待审批候选。参数不能替换节点身份或可执行命令。
- 相对路径在 Mac 和 Windows 使用一致校验；项目根目录 `.` 可以用于现有源码的最终交付。

## 可重复验证

最低检查为 `npm run typecheck`、`npm run build` 和 `npm run test:ci`。

| 测试入口 | 验证内容 |
| --- | --- |
| `test:workflow-roots` | 工作区直执行、项目外状态、真实路径与符号链接边界、文件变化失效 |
| `test:task-context` | Express/SQLite 任务关联、同根往返、跨根上下文筛选、去重与回滚 |
| `test:workflow-controls` | 检查点、问题、审批、暂停/取消和规划替换竞态 |
| `test:workspace-execution` | 写入互斥、只读并发、祖先目录、父子委派、取消释放 |
| `test:workflow-readonly-integration` | 多个只读编排整合时不升级锁或死锁 |
| `test:workflow-readonly-verification` | 真实命令证据、失败防伪、文件修改检查、恢复与写节点验收 |
| `test:workflow-resume-integrity` | 暂停/重启后文件失效、保留用户改动、合法后继覆盖与删除 |
| `test:workflow-targets` | 真实 Git 对比/整合、过期/脏状态、忽略文件和原索引保护 |
| `test:workflow-definitions` / `test:workflow-extensions` | 参数、能力、所有权、版本和完成门禁 |
| `test:workflow-public-activity` | 仅过滤内部控制回执、流式事件合并与顺序刷新 |

`scripts/test-workflow-experience-ui.mjs` 使用 Playwright 检查工作区目标、检查点、审批影响、流程参数、整合确认、模式往返、窄窗口及深色模式。浏览器和 Playwright 路径由环境变量提供，截图保存到工作台数据目录。

`npm run test:workflow-native-real` 是显式启用的真实模型测试，不属于离线 CI。它使用已配置的原生 Claude/Codex 连接和独立临时数据目录，验证现有项目修复、双向模型分工、运行中问题/调整、成果复用、最终验收、同任务对话续接及纯只读分析。递归比较项目条目，确保没有额外协议目录；退出后清除临时认证环境并扫描保留结果，不保留凭据。

## 工程边界

- `writeScope` 是调度、提示和事后核查边界，不是操作系统沙箱。
- 文件版本记录默认采用保守快照。已增加正向能力声明门禁和读取事件证据，但当前原生 Provider 未声明完整读取观测能力，继续使用全量保守范围。显式产物完整性检查移到 Worker，不缩减输出核验；大型项目仍有遍历元数据和 Worker 数据复制成本。
- 只读测试不能写业务文件。会生成覆盖率、缓存或测试结果的命令应使用写节点并声明范围，或将输出配置到系统临时目录。
- 任意动态 DAG、无审批自动改图、自动冲突解决和强制 Git 覆盖不属于本轮能力。
- Windows 分支在 Mac 上可以验证共享源码、类型、构建和平台无关回归；Windows 原生进程、打包与 Git 行为需要 Windows 环境验证。

架构约束参见 [任务编排基线](../architecture/task-orchestration.md) 与 [界面基线](../architecture/task-orchestration-ui.md)。

## 本轮最终验收记录

- Mac 分支：类型检查、生产构建和 115 项离线测试通过。
- Windows `main` 分支：共享源码的类型检查、生产构建和 114 项离线测试通过；没有在 Windows 系统上运行原生进程或打包测试。
- Playwright：21 个桌面、窄窗口和深色模式场景通过，客户端错误为空；任务切换、卸载和延迟响应竞态专项通过。
- 真实 Codex 主导：原项目修复、Claude 只读验收、检查点询问不改图、自动继续及同任务 Claude 对话续接通过。
- 真实 Claude 主导：原项目修复、检查点调整、复用已完成实现、Codex 只读验收及同任务 Codex 对话续接通过。
- 真实 Claude 纯只读：没有执行命令或写业务文件，静态检查的 command/exitCode 为 null，项目字节保持一致。
- 真实暂停恢复：Claude 完成写节点后安全暂停，外部修改产物再恢复，系统进入预期 needs_review；过期上游被阻止、下游没有启动、外部修改完整保留。
- 四类真实场景均未在项目内创建额外业务或协议目录，测试进程正常退出；临时凭据和原生配置已清理，保留证据扫描未发现明文密钥。

真实模型曾提交不合法工具参数，系统拒绝后模型自行纠正，报告保留这些记录。以上结果覆盖本轮验收范围，不代表任意模型输出、外部编辑或大型项目都不存在未知问题。
