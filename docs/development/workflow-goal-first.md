# 编排控制负担与上下文优化

日期：2026-10-09。范围：共享代码；Mac 和 Windows 采用相同协议、上下文和结果校验。

## 目标与保持的边界

让 Agent 把工作集中在用户的目标和成果上，由确定性宿主管理事务、状态、结构字段、文件证据和恢复。保持独立编排插件、计划审批、原生对话/委派能力和当前工作区直执行；新工作流不会在项目内生成额外任务目录。

## 已实现的机制

- 规划增加 `workflow_submit_plan`。普通计划一次提交，宿主规范化机械字段、生成结构审计记录并验证。大计划仍支持分批草稿和恢复。
- 新结果事务使用 v2。节点调用 `workflow_submit_result` 一次提交业务结论、产物和真实检查；长任务可按需 checkpoint。宿主控制身份、文件变化、命令证据和最终状态，返回简短回执。旧事务继续使用 v1，避免运行中的协议漂移。
- 共享业务规则由 `sharedContracts` 以 `id@version` 引用，宿主展开并校验。上下文投影保留相关祖先约束和输入，减少重复结果。
- 用户问题读取进度快照，不再为了问进度暂停节点。普通状态问答不调用模型；解释类问答使用无工具的受限模型会话。调整仍等待安全检查点并重新审批。
- 新计划默认标准验收；单节点省去重复整合，保留独立语义验收。严格模式和旧计划保留两个最终阶段。机器验收需明确审批且满足严格证据条件，否则保留语义验收。
- 宿主保存用户原文台账，记录来源执行、消息 ID 与版本。交接保留初始目标、最近用户请求、精确原文摘录和可检索引用；助手决定只作参考。原文超过提示预算时按需分页读取，不靠自动摘要丢失旧约束。
- 文件完整性重计算进入单 Worker 串行队列，完整检查显式产物目录及新增、删除、符号链接变化。原生读取事件记录来源与回退原因；缺少完整观测能力声明时继续保守工作区快照。
- 恢复记录命令/业务工具副作用及业务进展。不能证明安全重放或连续无进展时停止自动循环，不凭协议回执推定外部动作可以再次执行。

## 验证入口

用户要求的真实验收应优先使用当前可见工作台、现有端口和用户指定的测试工作区，保留任务与日志。独立回归后端仅是可选工具，需要用户明确选择；不得将它的结果描述成当前工作台中的测试。详细步骤见 [Native workflow validation](workflow-native-validation.md)。

| 测试 | 内容 |
| --- | --- |
| `scripts/test-workflow-protocol-v2.mjs` | 轻量提交、机械字段补全、事务版本、真实检查边界与提交回执 |
| `scripts/test-task-history-ledger.mjs` | 长用户原文、凭据脱敏、版本保留、预算、按引用/关键词恢复、同根隔离及旧数据 |
| `scripts/test-task-context-api.mjs` | HTTP 历史访问鉴权、来源绑定、上下文往返 |
| `scripts/test-workflow-file-integrity-async.mjs` | Worker 响应性、1801 文件输出树、忽略目录产物、新增删除与链接、精确读取能力门禁及保守回退 |
| `scripts/test-workflow-live-metrics.mjs` | 真实工具计数规则、响应字节、缺失 usage 为 null、外部行为验收器的正反例 |
| `scripts/test-workflow-native-e2e.mjs` | 原有真实模型场景与自然用户 CSV 修复目标，不向规划器预设节点 ID、模型、范围或验收答案 |

真实测试为显式付费运行。默认执行全部场景；`METACODE_NATIVE_TEST_CASES` 可以选择 `codex,claude,readonly,resume,open-goal` 的子集。报告记录实际规划/节点工具调用、协议回执可观察字节、各阶段时长与 API 请求流量。事件流没有真实 usage 时记录 null，不将字符数估算成真实 Token，也不把累计 usage 重复相加。保留的工具回执可能被日志层截断，字节统计代表已观察部分。

开放目标测试要求修复现有 CSV 导出程序，覆盖引号、逗号、换行、零金额、同步 API 和输入不变。模型自行形成计划，独立验收脚本位于测试项目之外且在模型执行完成后生成，防止验收结果只依赖模型报告。现有协议回归和真实模型测试分别报告；小型 fixture 不能替代大型项目质量评测。

## 实际边界

- 当前 Claude/Codex 不保证所有隐式文件读取均可观测，因此未启用缩小后的精确输入依赖；记录证据不等于宣称已完成动态污点追踪。
- 只有宿主可信适配器显式提供完整读取能力及隐式初始上下文路径，且全程没有未知工具、命令、恢复上下文或外部能力时，只读节点才可使用观察到的依赖集合。范围优化不替代输出与写入边界检查。
- Worker 将 CPU/同步文件遍历移出主事件循环，仍有扫描、快照传输、内存和磁盘 I/O 开销。1801 文件测试用于确认事件循环可以响应，不能证明任意大仓库的延迟上界。
- 机器验收是有限分支，研究和跨节点语义判断继续人工/模型审查。没有自动替换已批准 Provider、无限重规划或任意运行中改图。
- 成本上限、按结果质量自适应路由和大型真实项目的 A/B 性价比评测尚未在本轮凭上述测试证明。当前记录观测事实，为后续预算和评测提供基础。
- 本机为 Mac，共享 Windows 源码可以进行类型、构建与平台无关测试；Windows 原生运行和打包仍需 Windows 环境。

## 后续审查与可见工作台实测

以下补充针对上文验收后继续进行的审查，不覆盖历史记录：

- 规划与结果事务增加有界失败预算：相同错误连续出现三次、规划累计十二次或结果累计八次时停止协议修复，保留业务成果；参数校验失败和事务拒绝分别记录，避免重复计数。
- 未审批初始草稿采用标准验收、不强制文件交付，也不预设额外成果目录。用户明确批准的严格验收和已有计划合同仍保持原样。
- 原生只读提示按实际 Provider 生成。Claude 使用原生读取工具；Codex 可以执行只读文件查询命令，但不得修改文件、运行业务脚本或重复宿主测试。用户明确禁止命令时继续遵守该约束。
- 状态查询支持连续多句自然语言，直接返回带时间与版本的宿主快照；混合解释或修改请求保留既有处理路径。
- 编排转普通对话时刷新来源与完整用户原文台账，普通原生 Agent 可以按需读取绑定任务的私有历史工具。历史访问限定来源用户、同一执行根目录和任务身份。
- 文件哈希移入异步工作线程，缓存用文件身份与时间元数据失效；节点和整合流日志按 250ms 合并，工具完成与终态立即写入。活动持久化不覆盖暂停、取消等控制状态。
- 空白 SDK 回复事件不再以回复标题代替正文，历史中有原始空白证据的占位不再展示；未知 Agent 来源继承当前模型图标，系统消息使用系统图标。

可见实测包含 Codex 写入后 Claude 只读验收、Claude 规划的三个跨模型只读节点、同一任务编排转对话后真实读取历史，以及追加需求后 Claude 写入。原项目保持直执行，不生成协议目录；只读案例使用完整文件清单核对项目未被修改。测试报告保存在用户指定测试目录，模型原始日志与凭据不进入源码仓库。

以上机制已经落地，但自动决策知识库、原生工具完整隐式读取追踪、任意外部副作用一次性恢复、自适应模型路由和大型项目重复 A/B 质量成本评测仍未完成或未获实测证明。独立静态审查及小型真实任务不能证明整个项目不存在 Bug。
