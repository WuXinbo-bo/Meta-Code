# 原生会话核心闭环验收 · 2026-10-11

本轮将原生计划、人工审批和问题、自定义 Agent、完整历史 Fork 接入普通对话，并在当前可见工作台上实际运行 Claude 和 Codex。验收对象是下面列出的能力；不将 CLI 版本、能力声明或模型的口头回复视为所有官方功能已经通过验收。

## 实现与修正

- Codex 使用官方双向 App Server 协议承接需要原生控制的对话；已有默认执行路径和协作插件保持原有入口。
- Claude 使用官方 stream-json 权限回调，人工回答送回当前进程。请求绑定任务和拥有者，停止、退出和原生取消后立即失效。
- Fork 使用官方 `thread/fork` 或 `--resume --fork-session`；新分支有独立原生 ID，完整原生历史由 Provider 管理。
- Claude 自定义 Agent 由官方 CLI 读取原文件，避免简化的 `--agents` 对象覆盖 Hooks、Skills、Memory、MCP 和工具限制。解析器支持嵌套 YAML 和 Agent 子目录，不执行 YAML 标签或跟随符号链接。
- Codex 官方审批允许的拒绝枚举、文件修改类型和子 Agent 身份保留到工作台协议。子线程完成不会结束主线程，最终事件覆盖同一项的流式快照。
- 原生设置支持窄窗口；项目 Agent 的 Hook/MCP 显示官方目录信任提示。
- 搜索兼容层优先保留网关的官方 `/alpha/search` 请求、引用与加密状态；旧版回退只接受其能实际支持的语义，不能静默删除域名、时效或引用限制。

## 发现的问题与复测

Claude 的项目 Hook 初次没有执行。官方新版本要求先信任定义所在的项目目录：非交互对话仍可运行 Agent，但会跳过未授权的 Hook。通过原生终端确认指定测试目录后，shell 内置 Hook 和 Node 可执行 Hook 均产生了真实文件副作用。因此未通过自动写入信任记录或放宽权限来解决。

Codex 初次搜索能实际查询和读取 URL，但旧兼容路径拒绝精确域名限制。直连探测必须包含官方请求 ID；缺少 ID 的 HTTP 400 不能用于判定服务不支持。网关能处理精简请求并返回带 `results` 和 `encrypted_output` 的原生格式，但包含 CLI 上下文和控制字段的完整请求，在 `/v1/alpha/search` 和同源 `/alpha/search` 都返回 HTTP 200、业务码 500 的“路由不存在”。逐项对照复测确认：精简请求的成功不能代表完整 CLI 协议可用。因此增加协议校验、原生优先透传和缺失路由兼容，同时保留基础联网回退；没有删除官方控制字段或域名限制来伪装验收成功。完整域名过滤、私有引用读取和查找仍需网关支持原始请求后复测。

## 验证边界

Mac 分支执行类型检查、构建和 137 项离线测试。搜索边界测试覆盖原生透传、加密状态、私有引用、过滤参数、同源路径选择、真实 HTTP 错误、业务配额错误、回退限制和断连取消。Windows `main` 的共享内容通过独立的类型、构建和 136 项离线检查后同步。本机为 Mac，不能将这些检查作为 Windows ConPTY、打包或桌面进程启动的真实验收。

当前实测版本为 Claude Code 2.1.291、Codex CLI 0.162.0-alpha.17.2。模型、网关、CLI 版本、实验性团队服务和官方交互命令仍有各自边界。Skills、Memory、MCP 等高级字段保留给官方 CLI，并不等同于本轮对每一种组合逐项实测。

详细任务 ID、可见工作区、截图、脱敏快照及操作结果留在用户指定测试目录的 `reports` 中，不提交聊天、凭据或任务产物到仓库。
