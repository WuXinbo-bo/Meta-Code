# Meta 任务编排

任务编排是 Meta Code 面向复杂工作的独立执行系统。它不是“多开几个聊天”，而是一个经过计划审批、依赖调度、节点验收和成果集成的可恢复任务图。

它把复杂任务从一段不可控的长对话，转换成用户可以先审查、再执行、随时定位失败节点的工程流程。规划、执行和验收彼此分离，任何节点的自然语言结论都不能替代真实命令、文件产物或机器检查。

## 完整流程

1. 在真实工作区中选择“Meta 任务编排”，输入完整目标和期望交付。
2. 规划 Agent 生成静态 DAG，给每个节点配置 Provider、读写范围、Skill、MCP、依赖、验收条件、验证命令和交付物。
3. 工作台展示假设、风险、待确认问题和最终交付定义。用户可以批准、追加修改或重新规划。
4. 批准后，调度器只运行依赖已经满足的节点，并遵守并发上限与写入冲突约束。
5. 每个节点保存日志、尝试次数、结构化结果和产物。失败节点可以定点修复或重试。
6. 所有必需节点通过后，集成阶段复核机器结果、最终文件和交付标准，再生成统一成果。

## 界面中会看到什么

- 计划阶段展示目标、假设、风险、节点依赖和待确认问题，批准前不会运行节点。
- 执行画布展示每个节点的 Agent、状态、依赖、尝试次数和实时日志。
- 节点详情集中显示命令、工具调用、文件 Diff、验证结果与交付物。
- 失败节点可以单独重试；已经通过验收的节点不会被无故重跑。
- 最终成果区汇总产物目录、机器检查和集成结论，便于继续打开或交付。

## 关键保证

- 未批准的计划不会启动执行节点。
- 子 Agent 的自然语言回复不能单独证明完成，必须满足结构化验收。
- 暂停、恢复和失败重试不会要求重跑已经通过的节点。
- 计划版本、节点日志和最终成果保存在独立任务目录，便于追踪与恢复。
- 第一版使用审批冻结的静态 DAG，不在运行中任意改图。

## 适用场景

- 大型功能或跨模块重构。
- 发布前全量检查与多阶段修复。
- 研究、数据处理、写作和可视化等多角色生产流程。
- 需要明确成果目录、机器验证和审查记录的长任务。

简单问答、探索性需求或单文件修改通常使用普通原生/协作任务更高效。

## 与委派协议组合

[委派协议](delegation.md)负责一次执行中的主脑与子 Agent 协作；任务编排负责整个项目的计划、依赖、持久状态和验收。编排节点可以继续使用统一委派能力，但节点的完成状态必须回到编排器，由节点验收合同决定，而不是由子 Agent 自行宣布完成。
